에이전트는 포트폴리오와 사용자가 제공하는 실제 코드·설정·테스트를 대조해 현재 상태와 다음 작업을 안내합니다. 구조 질문에는 설계, 검증 질문에는 실험 계획을 함께 참조합니다. 본문의 Obsidian wikilink는 동일 이름의 Markdown 문서를 가리킵니다.

두 보조 문서는 역할을 나눠 관리합니다.

| 문서 | 여기서 정하는 것 |
|---|---|
| 아키텍처·장애 복구 설계 | 거래 상태·데이터 계약·트랜잭션 경계·복구 규칙 |
| 실험·대표 글 계획 | 설계를 어떻게 실패 주입·부하·SQL로 검증하고 결과·비용·대표 글로 남길지 |

규칙이 바뀌면 설계에서 수정하고, 그 규칙을 확인하는 시험 조건·통과 기준은 실험 계획에서 수정합니다. 실험에서 설계의 허점이 드러나면 설계의 선택과 이유를 갱신합니다. 같은 정책을 두 파일에 중복해서 정의하지 않습니다.
